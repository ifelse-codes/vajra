rec 7 — For item 4, remove a heredoc body from SCAN only when the WHOLE command is exactly one write unit and nothing else: an optional leading-space opener line in one of the shapes `cat > PATH <<'W'`, `cat >> PATH <<'W'`, `cat <<'W' > PATH`, `cat <<'W' >> PATH`, `tee PATH <<'W'`, `tee -a PATH <<'W'` (`tee` may also have ` > /dev/null`), then the body, then a line exactly equal to `W`, then only whitespace to the end. The delimiter must be QUOTED (`'W'` or `"W"`, where W matches `[A-Za-z_][A-Za-z0-9_]*`). PATH must be one unquoted token of `[A-Za-z0-9_./-]` (an optional leading `~/` is allowed). Strip only the body lines; keep the opener and terminator lines in SCAN. Every other shape stays scanned as today. That includes an unquoted delimiter (`<<EOF`), `<<-`, two heredocs, a here-string `<<<`, and any `|`, `;`, `&&`, `&`, `#`, `$`, backtick, `(`, `=` or quote anywhere on the opener line, or anything after the terminator.
Why: the class-level argument has three parts. (1) With a quoted delimiter, neither bash nor zsh expands anything in the body: no `$( )`, no backticks, no variables. The body is literal data, the same text the Write tool could write, and this guard never reads Write calls. (2) Only the opener line can feed the body to anything, and the strict shape sends it only to `cat`/`tee` and a plain file. (3) "Nothing after the terminator" rules out `cat > run.sh <<'W' … W` followed by `bash run.sh` in the same command, which the old guard blocks and which must keep blocking. The quoted-delimiter rule matters because of unquoted bodies like `$(echo ")"; git checkout -b session-191-x)`. Perl's balanced-paren match in `vajra_extra` stops at the quoted `)` and misses the checkout, but the shell runs it. Today the old SCAN still sees that line. Stripping it would fail open, so unquoted bodies must stay in SCAN. The path character set excludes zsh's `=cmd` expansion and glob qualifiers `(e:…:)`, which run code, and process substitution `>(…)`. This is tech-lead rec 2's allow-list, made into one exact shape.

rec 8 — Do the detection in one perl step that prints EITHER the command byte for byte OR "opener line + newline + terminator line", nothing else. Walk the lines in order and stop at the FIRST line exactly equal to W: no trimming, no `\s`, and a trailing `\r` or space does not count. Then require that what is left is only whitespace. In bash: `SRC=$(vajra_strip_heredoc "$CMD") || SRC="$CMD"; [ -n "$SRC" ] || SRC="$CMD"`, then `SCAN=$(sed -E "s/'[^']*'//g; s/\"[^\"]*\"//g" <<<"$SRC")` as today. Why: bash and zsh end a heredoc at the first line exactly equal to the delimiter. Perl must stop at that same line, or perl and the shell would disagree about where the body ends, and that is where a hole would come from. Removing whole lines before the line-by-line `sed` cannot change how any other line is read, because `sed` never pairs quotes across lines. So the change is confined to the removed lines. The byte-for-byte test is what proves that every other shape still goes through the old rule exactly.
