Most likely cause: this machine went idle/lost network for hours between the internal ~28min
of active work and the wrapper actually returning; the wall-clock watchdog measures real time,
which kept advancing through the stall, but the kill(-TERM) logic did not actually terminate
the process (the 'killed_by=timeout' marker is absent), so nothing capped it structurally.

Consequence: the harness's documented safety property ('a single stage is bounded by
TIMEOUT_SECS wall clock') did NOT hold in this run. The dollar cap held only because the
actual work done before the connection error happened to cost $3.30 < $5 — not because any
mechanism enforced it. A larger task under this same failure mode could have run past $5
with nothing stopping it until the process's own eventual, uncontrolled end.
